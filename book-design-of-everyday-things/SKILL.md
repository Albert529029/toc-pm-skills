# 《设计心理学》设计原则方法论

## 核心框架

### 框架一：七大交互设计原则

好设计 = 可发现性（能看出能做什么）+ 易通性（能理解怎么运作）。七个维度逐一体检：

| 原则 | 定义 | PM 自查问句 |
|------|------|------------|
| **示能 Affordance** | 物体属性与用户能力共同决定的可能互动 | 用户看一眼就知道能怎么操作吗？ |
| **意符 Signifier** | 传达操作信息的可感知信号（标牌/图标/颜色/形状） | 哪里该操作、怎么操作有明确提示吗？ |
| **映射 Mapping** | 控件与被控对象的空间/逻辑对应关系 | 控件位置和它影响的对象有自然对应吗？ |
| **反馈 Feedback** | 操作后即时传达结果的信息 | 用户操作后立刻知道发生了什么吗？ |
| **约束 Constraint** | 限制可能操作的四种力：物理/文化/语义/逻辑 | 设计是否主动阻止了错误操作？ |
| **概念模型 Conceptual Model** | 用户对"系统怎么运作"的内部理解 | 用户头脑里的模型和系统实际行为一致吗？ |
| **可视性 Discoverability** | 当前状态和可选操作对用户是否可见 | 用户不需要猜系统处于什么状态？ |

### 框架二：七步行动模型 + 双鸿沟诊断

用户每次交互循环经历七个阶段，前四步是"执行鸿沟"（怎么做），后三步是"评估鸿沟"（做到了吗）：

```
目标 → 意图 → 确认行动 → 执行 → 感知 → 解释 → 评估
 [####### 执行鸿沟 #######]  [### 评估鸿沟 ###]
```

**诊断用法**：用户卡在哪一步，就在哪里改：
- 卡在"确认行动"→意符缺失，用户不知道能做什么
- 卡在"执行"→映射不清或约束不足
- 卡在"感知/解释"→反馈缺失或延迟
- 卡在"评估"→概念模型与实际不符

### 框架三：人为差错分类与对策

| 类型 | 根因 | 典型表现 | 设计对策 |
|------|------|---------|---------|
| **失误 Slip** | 目标正确，执行出错 | 点错按钮、发错人 | 视觉区分 + 约束 + 撤销 |
| **失误子类：撷取性** | 熟悉动作序列劫持了计划动作 | 顺手把咖啡放冰箱 | 对破坏性操作加摩擦（确认/二次操作） |
| **失误子类：描述相似** | 目标和干扰项太像 | 删错文件 | 相似但高后果的操作物理隔离 |
| **失误子类：模式错误** | 误判系统当前模式 | 以为在编辑实则在预览 | 明确显示当前模式状态 |
| **错误 Mistake** | 目标/计划本身错误，概念模型偏差 | 选错功能、填错参数 | 改善概念模型 + 前馈提示 + 操作预览 |

**核心判断**：75%以上的事故被归因为"人为差错"，实际是设计差错。如果同类差错反复出现，一定是系统问题。

## 行动清单：C 端 PM 交互评审 Checklist

### 需求评审阶段
- [ ] 用户核心目标是什么？当前路径几步达成？
- [ ] 用户已有概念模型是什么？设计匹配它而非要求学习新模型？
- [ ] 是否在解决正确的问题（而非症状）？

### 设计评审阶段
- [ ] **意符**：每个可操作元素都有明确的操作提示吗？
- [ ] **映射**：控件排列是否与它影响的对象空间对应？
- [ ] **反馈**：每个操作都有即时（<1s）、明确、可理解的反馈吗？
- [ ] **约束**：高后果操作（删除/支付/提交）是否有防误触约束？
- [ ] **可视性**：系统当前状态用户是否无需猜测？
- [ ] **知识位置**：关键信息在"外界"（界面提示）还是强迫用户记在"脑中"？

### 上线前自查
- [ ] 撤销/恢复路径是否完整？用户能轻松回退吗？
- [ ] 是否有"诺曼门"——设计暗示的操作方式与实际不符？
- [ ] 反馈是否过度（噪音提示、频繁弹窗导致用户忽略所有提示）？
- [ ] 多步流程中断后能否恢复状态？

## 决策工具

### 双鸿沟定位决策树

```
用户反馈"不好用"
├─ "不知道怎么操作" → 执行鸿沟
│   ├─ 看不到能做什么 → 补意符 + 提升可视性
│   ├─ 不知道怎么做对 → 改映射 + 加约束
│   └─ 操作太复杂 → 减少步骤 / 拆解流程
└─ "操作了不知道结果" → 评估鸿沟
    ├─ 没有反馈 → 加即时反馈
    ├─ 反馈延迟/模糊 → 加快/明确反馈
    └─ 反馈了但不理解 → 修正概念模型对齐
```

### 示能 vs 意符 判断

物理产品优先用示能（形状传达用法），数字界面必须强意符（阴影/颜色/动效/文字），全新交互模式不依赖已有经验，需强意符引导+教学层。

## 常见错误

1. **诺曼门**：设计暗示的操作与实际矛盾。数字产品中：保存按钮无视觉反馈、表单按返回键清空数据。
2. **反馈缺失或过度**：按钮无声→反复按；持续闪烁→用户忽略所有警告。
3. **概念模型错位**：冰箱两旋钮用户以为分控冷藏/冷冻，实际控制冷量和冷气分配。
4. **功能主义**：购买时功能多=值，使用时=混乱。购买决策因素与使用满意度仅部分重叠。
5. **记忆转嫁**：密码复杂度要求越高→用户写便利贴→更不安全。
6. **归因谬误**：发现"人为差错"就停止追问。应连续五个"为什么"穿透到设计根因。

## 应用边界

**适用**：C 端交互设计评审、用户路径优化、可用性测试问题定位、新功能交互方案自查、错误率高的流程改造。

**不适用**：颠覆式创新（HCD 适合渐进式创新，颠覆式通常来自技术突破）、纯审美/品牌视觉决策、B 端复杂专业工具（专家用户愿学习，可容忍更高学习成本）。
